# 統家便利商店 自動補貨系統（課堂示範版）

大學資訊管理課程作業，使用假資料，不連接 ERP、物流系統或資料庫。

線上版：https://tongjia-auto-replenish.pages.dev/ （第一次開啟需載入約 20～30 秒）

## 系統目的

過去店長每晚盤點後要自行輸入補貨量，容易按錯或判斷錯誤；而「異常訂單攔截」又可能誤擋真正合理的特殊訂單（例如活動需要 999 件雨衣）。

本系統改為依近期銷售與現有庫存**主動產生建議補貨量**，店長可以接受、修改，最後確認後送出補貨單。

> 本系統定位為決策輔助工具，並非完全自動決策系統。

## 補貨模型

庫存管理模式：每日定期盤點制＋安全庫存管理（假設今晚下單、明早到貨）。

```
預測明日銷售 = 四捨五入( 最近 7 天銷售總和 ÷ 7 )        ← 7 日移動平均
安全庫存     = 四捨五入( 預測明日銷售 × 20% )
建議補貨量   = max( 0, 預測明日銷售 + 安全庫存 − 現有庫存 )
```

- **7 日移動平均**：簡單、可直接看懂預測依據，涵蓋平日與週末。
- **20% 安全庫存**：課堂示範的簡化設定；實際企業可依商品銷售波動、供貨時間及缺貨成本調整。

## 店長的角色

- 「店長最後補貨量」預設等於系統建議，店長可以直接修改，並填寫特殊訂單原因。
- **系統不會直接阻擋特殊大量訂單**，只會提醒「此補貨量明顯高於平常需求，請確認是否為特殊訂單。」
- 特殊訂單需由店長在「補貨單確認」頁勾選「確認特殊訂單（由店長負責確認）」後才能送出；也可以按「返回修改」。最後由店長負責確認。

## 狀態判定

由上往下判定，若同時符合多個條件，優先顯示較需要注意的狀態：

| 狀態 | 條件 |
|---|---|
| 🔴 特殊訂單 | 店長最後補貨量 > max(系統建議, 1) × 3，**且** 店長最後補貨量 − 系統建議 ≥ 20 |
| 🟠 低庫存 | 現有庫存 < 預測明日銷售 × 50% |
| 🔵 建議補貨 | 系統建議補貨量 > 0 |
| 🟢 正常 | 系統建議補貨量 = 0 |

特殊訂單用「比例＋差距」兩個條件，避免小幅修改被誤判（例如建議 1 件改成 4 件不會提醒）；系統建議為 0 時，比例條件以 1 計算。門檻常數 `SPECIAL_RATE`、`SPECIAL_MIN_DIFF` 定義在 `replenish.py`。

## 頁面

1. **首頁**：今日需補貨品項、低庫存、特殊訂單、建議補貨總量、狀態摘要
2. **自動補貨清單**：每項商品的建議量，可修改店長最後補貨量
3. **商品明細**：最近 7 天銷售紀錄與折線圖、完整計算公式
4. **補貨單確認**：特殊訂單確認、送出補貨單（顯示補貨單編號與送出時間，送出後鎖定）

錄影重來時，按側邊欄「重設示範資料」即可回到初始狀態。

## 本機執行

```bash
pip install -r requirements.txt
streamlit run app.py
```

## 線上版（Cloudflare Pages）

`index.html` 用 [stlite](https://github.com/whitphx/stlite) 在瀏覽器內執行同一份 `app.py`，不需要 Python 伺服器。更新部署：

```bash
mkdir -p dist && cp index.html app.py replenish.py dist/
npx wrangler pages deploy dist --project-name tongjia-auto-replenish --branch main
```

## 檔案

| 檔案 | 說明 |
|---|---|
| `app.py` | Streamlit 介面（四個頁面） |

| `index.html` | 線上版（stlite）入口 |
| `.streamlit/config.toml` | 白色簡約主題（本機版） |
